## Scheduling & Monitoring

### Schedule Management

Create, view, update, and delete schedules:

```bash
# List all active schedules
psb-quality-agent schedule list

# Create new schedule for daily checks
psb-quality-agent schedule create "Daily Quality Check" daily

# Create weekly schedule
psb-quality-agent schedule create "Weekly Audit" weekly

# Delete specific schedule
psb-quality-agent schedule delete schedule-1234567890

# Start the scheduler
psb-quality-agent schedule start

# Stop the scheduler
psb-quality-agent schedule stop
```

### Interval Options

| Interval | When | Default Time | Frequency |
|----------|------|--------------|-----------|
| hourly | Every hour | :00 | Every 60 minutes |
| daily | Every day | 02:00 UTC | Once per 24 hours |
| weekly | Every week | Sunday 02:00 | Once per 7 days |
| monthly | Every month | 1st at 02:00 | Once per month |

### Scheduler Configuration

```yaml
schedule:
  daily_scan_time: "02:00"
  weekly_scan_day: 0          # 0=Sunday, 6=Saturday
  weekly_scan_time: "03:00"
  timezone: UTC
```

### Programmatic Scheduling

```typescript
import { QualityAgentScheduler } from './psb-quality-agent-scheduler';

const scheduler = new QualityAgentScheduler();

// Create schedule
scheduler.createSchedule({
  id: 'daily-scan-' + Date.now(),
  name: 'Daily Quality Scan',
  interval: 'daily',
  enabled: true,
  operation: 'scan',
  created_at: new Date().toISOString(),
  updated_at: new Date().toISOString(),
  next_run_at: calculateNextRun('daily'),
  run_count: 0
});

// List all schedules
const schedules = scheduler.getSchedules();
schedules.forEach(s => console.log(`${s.name}: ${s.interval}`));

// Start scheduler
scheduler.start();

// Stop scheduler
scheduler.stop();
```

## Auto-Fix Capabilities

### Fixable Issue Types

The auto-fix feature can resolve:

| Issue Type | Action | Example |
|-----------|--------|---------|
| Text Replacement | Replace pattern | Fix outdated syntax |
| Missing Content | Add section | Add missing headers |
| Formatting | Standardize structure | Fix heading hierarchy |
| Links | Update broken references | Update or remove dead links |

### Configuration

```yaml
auto_fix:
  enabled: true                           # Enable feature
  dimensions:                             # Fixable dimensions
    - completeness
    - consistency
    - structure
    - links
  severity_levels:                        # Auto-fix severity
    - info                                # Auto-fix info issues
    - warning                             # Auto-fix warnings
  dry_run_by_default: false               # Apply changes immediately
```

### Usage Examples

```bash
# Preview fixes without applying
psb-quality-agent fix --dry-run

# Apply all fixes
psb-quality-agent fix

# Apply to specific dimension
psb-quality-agent fix completeness

# Dry run with specific dimension
psb-quality-agent fix --dry-run consistency
```

### Auto-Fix Limitations

Auto-fix **does NOT** apply to:
- ❌ Critical severity issues (require manual review)
- ❌ Fabrication or confidentiality issues
- ❌ Complex structural changes
- ❌ Issues requiring multi-file coordination
- ❌ Issues with interdependencies


Validate quality before commits:


## Trend Analysis & Metrics

### Trend Calculation

```
Delta = Current Score - Previous Score

Trend Classification:
  ↑ Improving:  Delta > +2 points
  → Stable:    -2 ≤ Delta ≤ +2 points
  ↓ Declining:  Delta < -2 points
```

### Velocity Measurement

```
|Delta| > 5:       ⚡ Fast    (significant change)
2 ≤ |Delta| ≤ 5:   🔄 Moderate (gradual change)
|Delta| < 2:        🐢 Slow    (minimal change)
```

### Historical Data

Trends calculated from:
- **Last 7 Scans:** Immediate trend (days)
- **Last 30 Days:** Monthly trend (weeks)
- **Full History:** Long-term patterns (months/years)

### Example Trend Analysis


## Performance & Optimization

### Performance Characteristics

| Operation | Time | Notes |
|-----------|------|-------|
| Scan 10 files | 2-5s | Typical file processing |
| Generate report | <1s | Multi-format generation |
| Trend analysis | <500ms | Historical calculation |
| Auto-fix 10 issues | 100-200ms | Per-fix application |

### Optimization Tips

1. **Parallel Processing**
   - Process up to 4 files concurrently
   - Configure via `scan.parallel_scans`

2. **Caching**
   - Cache results for 1 hour by default
   - Configurable via `advanced.performance.cache_ttl_seconds`

3. **Batch Operations**
   - Process issues in batches of 100
   - Configurable via `advanced.performance.batch_size`

4. **Incremental Scans**
   - Only rescan changed files
   - Enables faster re-runs

### Scaling

The agent efficiently handles:
- ✅ 100+ files
- ✅ 1000+ issues
- ✅ 30+ days of history
- ✅ Multiple simultaneous operations

## Troubleshooting Guide

### Common Issues & Solutions

#### Issue: Scan takes too long
```bash
# Solution: Exclude unnecessary directories
# Edit psb-quality-agent-config.yaml
exclude_patterns:
  - node_modules/**
  - .git/**
  - build/**
  - dist/**
  - .psb/**

# Or increase parallel scanning
scan:
  parallel_scans: 8
```

#### Issue: Auto-fix not applying
```bash
# Check auto_fix configuration
auto_fix:
  enabled: true          # Verify enabled
  severity_levels:
    - info               # Ensure severity included
    - warning
  dry_run_by_default: false  # Verify not dry-run

# Run with --dry-run to preview
psb-quality-agent fix --dry-run
```

#### Issue: Reports not generating
```bash
# Ensure report directory exists
mkdir -p .psb/reports

# Check file permissions
chmod -R 755 .psb

# Verify disk space
df -h .psb

# Check log file for errors
tail -f .psb/logs/quality-agent.log
```

#### Issue: Scheduler not triggering
```bash
# Verify scheduler is running
psb-quality-agent schedule list

# Check if schedules are enabled
# All schedules should show enabled: true

# Start scheduler explicitly
psb-quality-agent schedule start

# Monitor scheduler execution
tail -f .psb/logs/quality-agent.log | grep -i schedule
```

## FAQ & Best Practices

### Frequently Asked Questions

**Q: How often should I run scans?**
A: Daily scans recommended. Weekly deep-dive for comprehensive audit.

**Q: Can I customize quality dimensions?**
A: Yes, modify `quality_thresholds` in config YAML.

**Q: How far back does trend analysis go?**
A: By default 30 days. Configurable via `history.max_entries`.

**Q: Can I disable specific quality checks?**
A: Yes, toggle dimensions in `quality_checker.dimensions`.

**Q: How do I integrate with CI/CD?**
A: Add to pipeline: `npm run quality:check`

**Q: Can I use custom fix rules?**
A: Currently limited to built-in fixes. Extensibility coming in v2.

### Best Practices

1. **Schedule Regular Scans**
   - Daily automated scans
   - Weekly comprehensive audits
   - Monthly trend analysis

2. **Monitor Trends**
   - Review weekly trend reports
   - Act on degradation alerts
   - Celebrate improvements

3. **Prioritize Issues**
   - Fix critical issues immediately
   - Address warnings within sprint
   - Incorporate info items in backlog

4. **Use Auto-Fix Wisely**
   - Review dry-run output first
   - Enable only trusted fix types
   - Monitor auto-fix results

5. **Maintain History**
   - Keep full audit trail
   - Don't delete historical data
   - Use trends for planning
